# Lessons

- 2026-07-25(セッション8、ユーザー指摘「スマホだと全然できない」): 「375px でレイアウトが破綻しない」ことをモバイル対応と呼んでいた。実際にはレイアウト以前に**操作系が成立していなかった** — 盤面上のドラッグはボールとパドルを指で覆い、`pointerdown` が即発射で狙えない。マウス前提の入力をそのままタッチに流用しただけだった。**ルール: 入力を持つ画面のレスポンシブ確認は「見た目が崩れないか」ではなく「その入力デバイスでクリアできるか」で判定する。ポインタ操作は `pointerType` ごとに設計が別物になり得る(タッチは指が画面を隠す・ホバーが無い・押下と決定を分けられない)。** さらにレビューで、タッチ操作面を新設しても**旧操作面を残したままだと元のバグに戻れる**(数 px 外すと盤面に落ちる)、**マルチタッチでは `pointerId` を見ないと2本目の指がドラッグを奪う**という2点を指摘された。タッチ実装は必ず (1) 旧操作面の無効化 (2) pointerId の所有権 (3) `pointercancel` の3点をセットで確認する。

- 2026-07-25(セッション7、ユーザー指摘「右上の濃い部分残機ですか？みえづらすぎる」): 残機表示をコンテンツと同じ色域(草の緑 level4)で、しかもコンテンツ(草グリッド)の**上に重ねて**描いていたため、草の濃いセルと区別がつかなかった。**ルール: ステータス表示(HUD)はコンテンツの色を借りない。自分で決めた「色に意味を持たせる規則」は UI 全域に適用し、canvas の中も例外にしない。加えて、情報を情報の上に重ねない — 背景が無地の場所に置く。**「初見の人がこれを何だと思うか」を必ず自問する(今回はユーザーが疑問形で尋ねてきた時点で discoverability が失敗している)。対応: 残機=アンバーの「予備のボール」(実際のボールと同色・同径)+ `LIFE` ラベルを、草の直下の無地帯に配置。

- 2026-07-25(セッション5計画、ユーザー指摘): デザインモックのピクセル文字で、未定義グリフ(Z/H/I)を黙って S にフォールバックさせた結果「KUSAKUZUSHI」が「KUSAKUSUSSS」と表示された。**ルール: 文字を描画するデータ(グリフマップ等)は、対象文字列の全文字が定義済みであることを先に検証する。未定義は静かな代替ではなく即エラーにする。** 本実装 demo-grid.ts では「KUSAKUZUSHI の各文字にグリフが存在し、期待どおりのセルパターンが出る」ユニットテストを必須とする(todo.md セッション5 Phase 3 に反映済み)。モックであっても表示内容が仕様(ワードマーク)そのものである以上、手抜きフォールバックは仕様違反になる。
